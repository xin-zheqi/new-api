# 经典前端设置入口与暗色主题修复（2026-10-19）

本次只修改 `web/classic` 的前端、测试及翻译，不修改后端转发、流式处理、计费、数据库或 Redis 逻辑。

## 渠道与余额

- 经典前端新增渠道类型选项 **New API（60）** 和 **Sub2API（59）**，两者要求填写站点 API 地址，并支持获取模型列表。
- 余额查询根据保存的渠道类型选择后端接口，不根据域名自动识别。已有站点如果仍配置为 OpenAI，需要在渠道编辑中选择对应类型。
- 保留点击余额更新的入口，同时在这两类渠道的“更多”菜单加入“余额查询”，余额列隐藏时也能操作。
- 并非所有非 OpenAI 渠道都不支持余额查询。前端允许列表与当前后端保持一致，包含 OpenRouter、Moonshot、SiliconFlow、DeepSeek、New API、Sub2API 等。
- 不支持的渠道类型和多密钥渠道显示 `—`，通过悬浮说明解释原因，不再提供必然失败的点击操作。Codex 继续使用原有帐号信息入口。
- 原有批量余额查询规则保持不变。

## 设置入口去重

保留原来的设置入口和 Semi UI 表单，移除经典前端重复的“请求策略”页及其引导链接：

| 功能 | 编辑位置 |
| --- | --- |
| 重试次数 | 运营设置 → 通用设置 |
| 重试状态码、渠道测试、自动禁用与恢复 | 运营设置 → 监控设置 |
| 屏蔽词过滤 | 运营设置 → 屏蔽词过滤设置 |
| 会话保持与路由规则 | 模型相关设置 → 渠道亲和性 |
| 全局服务器地址 | 系统设置 → 服务器地址 |

后端已融合的请求策略、校验和原子保存接口继续保留。原监控表单新增测试模式和并发数，支持 `scheduled_all`、`auto_ban_only`、`passive_recovery`；不再把 `auto_ban_only` 误改为旧模式。模式与兼容字段一起提交，测试间隔保留小数；状态码仍使用原有校验和范围显示。

监控和屏蔽词表单通过既有策略接口一次保存修改的策略项，余额提醒仍使用原选项接口，不会额外提交测试模式。通用设置继续编辑重试次数，并正确处理后端拒绝的值，避免误报保存成功。会话规则的原子保存与扩展字段保留逻辑不变。

已经保存的 `?tab=request-policies&policy=...` 链接自动跳转到原运营或模型设置页，不显示第二套编辑器。默认前端未在本次修改范围内。

支付页只读展示全局服务器地址，保存支付选项不再重发旧地址；支付专用 `CustomCallbackAddress` 仍独立保留。修复清空回调地址不能保存的问题，空字符串恢复后端既有的全局地址回退规则。

对移除重复页后的经典前端 14 个设置分类及其可达组件进行了静态字段审查，并检查重复项的保存逻辑。识别出 253 个不同字段名；跨分类同名的 `name`、`slug`、`url` 分别属于不同业务对象，不是同一个全局配置。动态生成的字段不能仅凭静态扫描证明无重复。

全局默认与渠道覆盖、站点提醒总开关与个人通知分类、全局屏蔽词与用户内容审计规则、不同维度的限流仍有各自作用，未作为冗余删除。

## 主题与界面

渠道优先级编辑器使用 Semi UI 主题变量，表格、边框、文字、焦点和禁用状态随主题切换。其原生下拉列表明确跟随应用主题，即使操作系统主题相反也保持一致。无默认页脚的弹窗补充 24px 底部内边距，与左右留白一致；空列表、长列表、变更预览及撤销按钮均保留间距。原设置页继续使用 Semi UI 控件及其暗色主题，没有新增醒目的提示横幅。
