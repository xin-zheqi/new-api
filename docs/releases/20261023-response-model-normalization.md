# 响应模型名称统一与管理员日志提示

下游请求使用的模型名现在是响应模型元数据的统一展示值。即使 New API 没有配置模型映射、只有上游网关进行了重定向，也不会在这些响应字段中返回上游名称。

## 行为

- 普通 JSON、SSE 流式事件及 Realtime 的已知模型元数据位置统一使用 `RelayInfo.OriginModelName`，包括 `model`、Gemini `modelVersion` 和 Responses/Claude/Realtime 的对应封装字段。
- 只修改协议元数据，不递归替换正文、工具参数、工具结果或扩展对象里的同名字段。原始 usage、路由模型和计费模型不因此修改。没有模型元数据的协议响应不额外注入字段。
- 纯文本、字幕和二进制音频保持原有格式；转录正文即使本身是一段 JSON，也不能被当作模型元数据改写。
- 在协议转换之前记录上游声明的模型名。与下游请求名称不一致时，在现有 `other.admin_info.response_model_mismatch` 中记录请求名称和上游响应名称，包括空响应校验提前拒绝的 JSON/SSE 失败响应。
- 记录按单次渠道尝试隔离、去重，最多保存 8 个名称，每个最多 256 UTF-8 字节，超限附带省略标记。重试下一渠道时不会继承上一渠道的名称。
- 名称不一致仅为诊断信息，不会新增报错、禁用渠道或触发重试。本地有意配置的模型映射也可能出现此提示。
- 错误日志仍遵循原有 `ERROR_LOG_ENABLED` 配置；需要查看失败请求的记录时，部署环境应设置 `ERROR_LOG_ENABLED=true`，本次不会强制改变该开关。
- 普通用户和令牌日志查询沿用后端 `admin_info` 移除逻辑，无法取得新增诊断字段。经典与新版前端均检查管理员权限。

上游响应名称是对方声明的标识，不代表对实际运行模型的独立鉴定。

## 页面

两套前端在日志模型名称下方增加低调的信息图标和“响应模型不一致”小字。点击或键盘操作可查看请求模型和上游响应模型，日志展开详情同步显示。使用各自的主题颜色，支持浅色、深色及全部 7 种语言。历史日志没有诊断字段时保持原有显示。

## 验证

- Go 1.26.10：`go test ./relay/... ./service ./controller ./model -count=1` 通过；最终镜像构建再次运行 `go test ./relay/... ./service -count=1` 并构建根模块。
- `cd relaykit && GOWORK=off go build ./...` 通过。
- 新版：`bun run typecheck`、变更文件 lint/格式检查、4 项组件回归和生产构建通过。
- 经典：变更文件 ESLint/格式检查、4 项组件回归和生产构建通过。
- 组件回归覆盖管理员权限、无诊断记录、键盘打开、上游字符串转义和长名称详情。
- 隔离 Docker 接本地模拟上游，验证 Chat/Responses JSON 与 SSE、compact、本地映射与上游独立映射、同名响应、Claude/Gemini 原生及 Claude 转 Chat、嵌入、图片和搜索；检查用量及正文保持原样、管理日志和用户/令牌日志权限隔离，以及提前失败仍记录诊断且无额外消费日志。
- 在真实浏览器中检查两套前端浅色/深色弹层和展开详情。

没有修改数据库结构、ORM 依赖或查询方式；本次没有使用真实收费上游进行请求验证。

发布镜像：`thefoolishfox1/new-api:model-normalization-20261023`，验证成功后同步 `latest`。具体发布摘要以本地验证目录中的 `release.json` 为准。
