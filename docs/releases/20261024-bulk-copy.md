# 请求深拷贝批量复制优化 — 2026-10-24

## 改动范围

本次生产代码仅修改 `common/copy.go`：增加 `json.RawMessage` 和 `[]byte`
两个 copier 类型转换器，以 `bytes.Clone` 批量复制替代逐字节反射复制。
生产代码 diff 为增加 16 行、删除 1 行，保留 `DeepCopy: true`、
`IgnoreEmpty: true`、nil 源错误及其他类型的原有复制路径。

字节内容不解析、不序列化、不解密；新缓冲区与源数据独立。保留 nil、
非 nil 空切片、显式零值和 false，避免渠道改写污染原始请求及后续重试。
没有引入缓冲池、请求历史缓存或共享可写请求对象。

实际消费者为 Responses、Chat、Claude、Gemini、Image、Audio、Embedding、
Rerank 八类请求处理器。无数据库查询、结构、驱动、Redis、计费公式、
重试策略、思考/工具修复策略或前端变更。经典和新版前端沿用上一版资源。

## 性能测量

命令：在 `--cpus=2 --memory=2g -e GOMAXPROCS=2` 的容器中执行
`go test ./common -run '^$' -bench BenchmarkDeepCopyResponses -benchmem -count=3`。
物理 CPU 为 i7-13700K；容器配额不等同于任意云服务器的 2 核性能。
下表为三次采样中位数，仅衡量 Responses DTO 深拷贝步骤。

| 文本负载 | 旧逐字节反射 | 新批量复制 | 单次减少 |
| --- | ---: | ---: | ---: |
| 空文本（input JSON 30 字节） | 0.0111 ms | 0.0101 ms | 约 0.001 ms |
| 16 KiB | 0.8033 ms | 0.0122 ms | 约 0.791 ms |
| 256 KiB | 12.5027 ms | 0.0508 ms | 约 12.452 ms |
| 1 MiB | 50.1842 ms | 0.1369 ms | 约 50.047 ms |

1 MiB 场景每次分配从约 2.108 MB / 1,048,635 次降到 1.061 MB / 35 次。
空文本场景因 converter 配置增加，分配字节数从 2,640 增至 3,920，但时间没有
回退；不能概括为所有小请求都显著节省内存或延迟。其他协议如果不含较大的
原始字节字段，收益有限。整次请求仍包含网络、排队、上游推理等时间。
